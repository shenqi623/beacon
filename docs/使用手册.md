# Beacon 使用手册

Beacon 是一款本机桌面应用，用于把新站点自动接入 **GTM / GA4 / Search Console**。  
配置、凭证与任务数据都保存在本机，不会写入安装包。

> 当前版本（0.1.0）：支持可视化配置、授权登录、授权检查，以及完整的添加站点自动化流程（含监听预设、失败继续、健康检查）。

> **说明：** 下文涉及 **Google Cloud Console / Analytics / Tag Manager** 网站时，菜单与按钮名称一律按 **英文界面** 书写；说明文字仍为中文。Beacon 应用内按钮保持中文。

---

## 1. 使用前准备

请先准备好：

1. 一个 Google 账号（需能登录 [Google Cloud Console](https://console.cloud.google.com/)）
2. 已有 **GA（Analytics）账号** 与 **GTM（Tag Manager）账号**  
   Beacon **不会**帮你创建这两个账号，只使用你填入的账号 ID
3. （可选）本机 HTTP 代理，例如 `http://127.0.0.1:7897`（国内访问 Google API 常用）

---

## 2. 获取 Client ID 与 Client Secret

以下步骤均在 **英文版** Google Cloud Console 中操作。

### 2.1 创建 / 选择项目

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)
2. 点顶部的 **Select a project**
3. 在弹窗中点 **New project**
4. **Project name** 填 `Beacon`（可自定义），点 **Create**
5. 创建完成后，确认顶部项目选择器已显示该项目名（不再是 Select a project）

### 2.2 启用所需 API

1. 左侧菜单进入 **APIs & Services** → **Library**  
   （也可在顶部搜索栏输入 `Library`）
2. 分别搜索并打开下列 API，进入详情页后点 **Enable**：

| API 名称（搜索用） | 用途 |
|---|---|
| Google Analytics Admin API | 创建 GA4 属性 / 数据流 |
| Tag Manager API | 创建容器、标签、发布 |
| Google Search Console API | 加入站点、提交 sitemap |
| Google Site Verification API | 网站所有权验证 |

### 2.3 配置 OAuth consent screen

1. 进入 **APIs & Services** → **OAuth consent screen**
2. 若提示选择类型：**User Type** 选 **External**，点 **Create**
3. **App information** 中填写：
   - **App name**：例如 `Beacon`
   - **User support email**：选你的邮箱
   - **Developer contact information**：填你的邮箱
4. 其余可先保持默认，一路点 **Save and Continue**  
   - **Scopes** 页可先跳过（点 **Save and Continue**）  
   - Beacon 授权时会向用户请求所需权限
5. 若 **Publishing status** 为 **Testing**：
   - 打开 **Test users**
   - 点 **Add users**，加入你自己的 Google 邮箱，保存  
   - 否则授权时可能提示应用未完成验证 / 无权限

> 处于 Testing 时，只有 Test users 列表中的账号能完成授权。本阶段一般不需要正式 Publish。

### 2.4 创建 OAuth 客户端（拿到 ID / Secret）

1. 进入 **APIs & Services** → **Credentials**
2. 点 **+ Create credentials** → **OAuth client ID**
3. 若尚未配置同意屏幕，按提示先完成上一节
4. **Application type** 选 **Desktop app**
5. **Name** 随意，例如 `Beacon Desktop`
6. 点 **Create**
7. 弹窗中会显示：
   - **Client ID**
   - **Client secret**
8. 复制并妥善保存；之后也可在 Credentials 列表中点开该客户端再次查看

**重要说明：**

- 必须选 **Desktop app**，不要选 **Web application**
- Beacon 使用本机回环地址 `http://127.0.0.1:随机端口` 接收授权回调；Desktop 类型下 Google 通常允许此类回调，**一般无需再手动填写 Authorized redirect URIs**
- Client secret 相当于钥匙，不要提交到 Git、不要发到公开聊天

## 3. 在 Beacon 中完成配置与授权

### 3.1 安装 / 打开

- 本地打包产物常见路径：`src-tauri/target/release/bundle/`（Windows 为 NSIS；macOS 为 dmg/app）
- GitHub：仓库 Actions 可手动 **Run workflow** 打包；推送 `v*` 标签可生成 Draft Release（Windows + macOS）
- 开发调试：`pnpm tauri:dev`

### 3.2 填写 OAuth 与保存

1. 打开左侧 **「配置」**
2. 填入 **Client ID**、**Client Secret**
3. 如需代理：勾选 **启用代理**，确认地址（如 `http://127.0.0.1:7897`）
4. 填写 **GA 账号 ID**、**GTM 账号 ID**
5. 按需调整时区、币种、执行节奏（可先用默认值）
6. 点底部 **「保存配置」**（修改代理等选项后也会出现「有未保存的更改」提示）

保存后，Client ID / Client Secret 状态应变为 **「已设置」**。

### 3.3 授权登录（获取 Refresh Token）

1. 点 **「授权登录」**（若有未保存更改，会先自动保存再打开浏览器）
2. 系统浏览器会打开 Google 授权页
3. 登录账号 → 勾选全部权限 → 允许（英文页常见按钮为 **Continue** / **Allow**）
4. 浏览器出现成功提示后，可关闭该页并回到 Beacon

成功后：

- **Refresh Token** 状态变为 **「已设置」**
- Token 自动写入本机数据目录，界面**不会**显示完整 Token

若提示缺少权限：重新点「授权登录」，并在 Google 页面勾选全部权限。

### 3.4 授权检查

1. 打开左侧 **「授权」**
2. 点 **「检查授权」**
3. 确认各项为通过：凭证、Access Token、权限范围、GA 账号、GTM 账号

全部通过后即可在 **站点** 页添加并执行任务。

## 4. 添加与管理站点

### 4.1 添加站点

1. 打开左侧 **「站点」**
2. 填写 **域名**、**站点名称**（可选填写 sitemap；留空则默认 `https://{域名}/sitemap.xml`）
3. 勾选 **GTM 监听预设**（默认全开，仅添加时可配置）：
   - **点击** → GA4 事件 `click`
   - **出站链接** → GA4 事件 `apk_download`
   - **表单提交** → GA4 事件 `form_submit`
4. 点 **「添加并开始」**；或先点 **「先预演」** 只看将执行的操作，不创建资源

每个站点都会各自创建一套资源（**不是**只换一个 GTM ID）：

| 每站独立 | 多站共用 |
|---|---|
| GTM 容器（`GTM-XXXX`）与安装代码 | 配置里的 GA / GTM **账号** ID |
| GA4 属性、Web 数据流、衡量 ID（`G-XXXX`） | 同一套 OAuth 授权 |
| GTM 发布版本、监听标签 | 时区、币种、代理等应用设置 |

### 4.2 自动化步骤（顺序）

1. 创建 / 复用 GTM 容器  
2. 创建 / 复用 GA4 属性  
3. 创建 / 复用 Web 数据流  
4. 发布 GTM（写入 Google 代码与所选监听，并发布版本）  
5. **等待部署**：把详情里的 GTM 代码贴到网站后，点 **「检查部署」**  
6. 验证 Search Console 所有权（方式为 Tag Manager）  
7. 加入 Search Console 并提交 sitemap  

全部成功后状态为 **「完成」**。

### 4.3 网站上要装什么

- **只需安装该站的 GTM 容器代码**（详情页提供 `<head>` 与 `<body>` 两段）
- **不必**再单独贴 GA4 / GSC 验证代码；GA4 经 GTM 的 Google 代码上报，GSC 用 Tag Manager 方式验证
- 检查部署会抓取站点首页 HTML，确认是否包含该站 `GTM-XXXX`（仅前端动态注入、原始 HTML 没有的，检测不到）

### 4.4 列表、进度与详情

- 左侧 **站点列表**：选择站点；可点 **「进度 / 折叠」** 展开该站执行步骤  
- 右侧 **详情**：安装代码、产出 ID、监听预设、失败继续 / 检查部署、健康检查  
- 站点较多或进度展开后，列表与详情各自滚动，互不影响

### 4.5 失败继续与删除

- 任一步失败会停在该步并显示原因；点 **「从失败处继续」** 从失败步重试，已完成步骤不重复执行  
- **「删除站点」** 只删本机任务记录，**不会**删除 Google 上已创建的容器 / 属性等资源

### 4.6 健康检查

站点非执行中时，详情可点 **「健康检查」**，复核：

1. 首页是否仍含该站 GTM ID  
2. GTM 线上版本是否仍含 Google 代码与已勾选的监听事件标签  
3. GA4 属性与数据流是否仍存在且衡量 ID 一致  
4. Search Console 网址前缀与已提交的 sitemap 是否仍可访问  

结果保存在本机站点记录中。

## 5. 账号 ID 从哪里找

### GA 账号 ID

1. 打开 [Google Analytics](https://analytics.google.com/)
2. 左下角进入 **Admin**
3. 在 **Account** 列打开 **Account settings**（或账号设置相关项）
4. **Account ID** 为一串数字（例如 `123456789`）

### GTM 账号 ID

1. 打开 [Google Tag Manager](https://tagmanager.google.com/)
2. 进入对应账号的 **Admin** / 账号管理相关页面
3. 可见 **Account ID**（一串数字，例如 `6001234567`）  
   注意：这是 **Account ID**，不是容器的 `GTM-XXXX`

## 6. 本机数据目录

界面可显示类似路径，并用 **「打开数据目录」** 打开：

```text
C:\Users\<你的用户名>\AppData\Roaming\app.beacon.desktop
```

作用：

- `config.json`：配置与 OAuth 凭证  
- `beacon.db`：站点任务与步骤状态  
- **不在安装包内**；换电脑或清空该目录后需重新配置与授权

## 7. 常见问题

### 授权提示「请先填写 Client ID 和 Client Secret 并保存」

先填写并点 **保存配置**，再点授权登录。

### Refresh Token 一直显示「未设置」

说明尚未成功授权。按第 3.3 节完成授权；成功后会变为「已设置」。

### 浏览器授权页报 redirect_uri 相关错误

确认创建时 **Application type** 是 **Desktop app**。若误建成 **Web application**，请删除后按 Desktop app 重建。

### 授权页提示应用未验证 / 无法继续

OAuth consent screen 仍为 **Testing** 时，把当前 Google 账号加入 **Test users**。

### 检查授权时网络超时 / 连接失败

开启代理并保存正确地址；确认代理软件允许本机程序走代理。发布 GTM 若长时间失败，也可先临时关闭代理再点「从失败处继续」试一次。

### 发布 GTM 提示 Not found / permission denied

常见原因：GTM 后台里该容器已被删除，或本机记录的容器路径失效。用较新版本的 Beacon 从失败处继续时，会尝试按站点名重新查找 / 创建容器。若 GTM ID 变了，网站上的安装代码也要换成详情里最新的。

### 检查部署一直找不到 GTM ID

确认代码已出现在首页**原始 HTML**中（不是仅运行后由 JS 注入）。可用浏览器「查看网页源代码」搜索 `GTM-`。

### Client Secret / Refresh Token 会不会打进安装包？

不会。只保存在本机数据目录；安装包里没有你的密钥。

### 控制台顶部一直是 Select a project

说明还没选中项目。按第 2.1 节 **New project** 创建，或从列表中选中已有项目。

---

## 8. 安全建议

1. 不要把 Client Secret、Refresh Token 发到公开渠道或提交到代码仓库  
2. 不要把整个 `app.beacon.desktop` 数据目录分享给他人  
3. 怀疑泄露时：在 Cloud Console 的 **Credentials** 中重置 secret，并在 Beacon 中清除后重新授权  
4. 界面「清除」可删除本机已保存的对应字段
